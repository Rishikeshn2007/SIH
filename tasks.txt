Build a lightweight Flask-based navigation server for my Unmanned Ground Vehicle project.


The UGV is approximately:
- Length: 35 cm
- Width: 20 cm

For now, use the raw grid without vehicle-size obstacle inflation. Keep the architecture extensible so this can be added later.

--------------------------------------------------
MAIN OBJECTIVE
--------------------------------------------------

Create a Flask server that manages navigation between a source and destination on the grid.

The workflow should be:

1. User provides a source coordinate.
2. User provides a destination coordinate.
3. Flask server loads/uses the obstacle matrix generated by SLAM.py.
4. Flask server passes the matrix to RoutePlanner.
5. RoutePlanner calculates a collision-free route.
6. Server stores the planned route and current navigation state.
7. ESP32/ESP8266 periodically sends its current position and heading.
8. Server determines the next grid coordinate.
9. Server determines the required movement command.
10. Server returns the command to the vehicle.
11. Vehicle executes it and sends its updated state.
12. Repeat until destination is reached.

This must be a CLOSED-LOOP navigation system.

Do NOT assume that sending a command means the vehicle successfully reached that coordinate.

--------------------------------------------------
VEHICLE → SERVER PACKET
--------------------------------------------------

Create an endpoint:

POST /car/state

The ESP32 should send JSON similar to:

{
    "x": 5,
    "y": 7,
    "heading": 90,
    "running": true
}

Where:

x = current grid X/column coordinate
y = current grid Y/row coordinate
heading = current vehicle orientation in degrees
running = whether the vehicle is currently running

Use a consistent coordinate convention throughout the entire application.

Document the coordinate convention clearly.

Heading can initially use:

0   = North
90  = East
180 = South
270 = West

Keep heading handling modular so this can later support continuous angles.

--------------------------------------------------
SERVER → VEHICLE PACKET
--------------------------------------------------

The /car/state endpoint should return JSON similar to:

{
    "next_x": 5,
    "next_y": 8,
    "command": "move_forward",
    "speed": 150,
    "turn_angle": null
}

Possible commands initially:

move_forward
move_backward
turn_left
turn_right
stop

speed must be an integer between:

0 and 200

turn_angle should be:

null

when no turn is required, or

an angle in degrees

when a turn is required.

--------------------------------------------------
NAVIGATION START ENDPOINT
--------------------------------------------------

Create:

POST /navigation/start

Request:

{
    "source": [1, 1],
    "destination": [18, 18]
}

When this endpoint is called:

1. Validate the source.
2. Validate the destination.
3. Load the obstacle matrix.
4. Instantiate/use RoutePlanner.
5. Calculate the route.
6. Store the route in the server navigation state.
7. Set the current navigation index.
8. Return the calculated route and basic navigation information.

Example response:

{
    "status": "started",
    "source": [1, 1],
    "destination": [18, 18],
    "route": [
        [1,1],
        [1,2],
        [1,3]
    ],
    "route_length": 25
}

--------------------------------------------------
ROUTE FOLLOWING
--------------------------------------------------

When the vehicle sends:

{
    "x": 5,
    "y": 7,
    "heading": 90,
    "running": true
}

the server should:

1. Update the vehicle's current position.
2. Determine where that coordinate exists in the planned route.
3. Determine the next coordinate.
4. Compare current heading with the direction toward the next coordinate.
5. Decide whether the vehicle should:
   - move forward
   - turn left
   - turn right
   - move backward
   - stop

Do not simply return the next coordinate.

The server must calculate the movement command from:

current position
+
current heading
+
next route coordinate

--------------------------------------------------
TURN LOGIC
--------------------------------------------------

For the first implementation, use grid-based 90-degree directions.

Example:

Current:
(5,7)

Next:
(5,8)

If heading already points toward the next cell:

command = move_forward

If the next cell requires a left turn:

command = turn_left
turn_angle = 90

If it requires a right turn:

command = turn_right
turn_angle = 90

If the destination is reached:

command = stop
speed = 0

Keep this logic isolated in a navigation/controller class rather than embedding complicated logic directly inside Flask endpoints.

SAFETY / ROBOT CONTROL
--------------------------------------------------

Implement basic fail-safe behavior.

If:
- navigation is not started
- route is unavailable
- invalid position is received
- destination is reached
- navigation is stopped

speed = 0

Do not continue sending movement commands when navigation state is invalid.

Also add a configurable communication timeout. If the vehicle stops reporting for too long, the navigation controller should enter a safe stopped state.
